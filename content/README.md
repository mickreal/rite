# Rite content engine

Programmatic content for styles 1, 2 and 6 in `docs/gtm-plan.md` §2. Everything here sits outside the Worker:
the root `tsconfig.json` and `vitest.config.ts` only see `src/` and `test/`, and nothing in `src/` imports from here.

| Style | What | Source | Output |
|---|---|---|---|
| 1 | Dial screen-recording, 1080×1920, ~20 s, captions burned in | `clips/render-clip.ts` + `clips/cohorts.json` | `out/clips/<cohort>.mp4` |
| 2 | Sign card, 1080×1350 still | `remotion/src/SignCard.tsx` | `out/signs/sign-<sign>.png` |
| 2 | Sign card, 1080×1920, 8 s animated | `remotion/src/SignCard.tsx` (`SignCardVertical`) | `out/signs/sign-<sign>-vertical.mp4` |
| 2 | Cohort card, 1080×1350 | `remotion/src/CohortCard.tsx` | `out/cohorts/cohort-<id>.png` |
| 6 | Quote card (cream), 1080×1350 | `remotion/src/QuoteCard.tsx` | `out/quotes/quote-<id>.png` |
| 2/6 | Cohort or quote card on a 1080×1920 frame, 10 s push-in (TikTok / Reels slot) | `remotion/src/VerticalCard.tsx` | `out/cohorts/cohort-<id>-vertical.mp4`, `out/quotes/quote-<id>-vertical.mp4` |
| — | Instagram carousel slides (kit (e)), 1080×1350, cream | `remotion/src/CarouselSlide.tsx` + `remotion/carousels.json` | `out/carousels/<carousel id>-NN.png` |
| 5 | Caption-free result screen, 1080×1920 (green-screen backdrop) | `clips/render-clip.ts --stills` | `out/stills/<cohort>-summary.png` |

`out/` is git-ignored. `samples/` has four stills and one clip so you can see the look on GitHub.

## Setup (once)

- Root deps: `npm ci` in the repo root (wrangler + playwright).
- Remotion: `cd content/remotion && npm ci`.
- Tools: bun, ffmpeg (with libfreetype), Chromium. Scripts use `/opt/pw-browsers/chromium` when it exists; set `CHROMIUM=/path/to/chrome` otherwise.
- Playwright's `recordVideo` needs its own ffmpeg build: `npx playwright install ffmpeg` (root).
- Fonts are in `fonts/` (Bricolage Grotesque, Hanken Grotesk; SIL OFL 1.1, from github.com/google/fonts, licences alongside). The static cuts that ffmpeg uses are generated by `python3 fonts/make-static.py` (needs `pip install fonttools`) and are committed.

## Render everything

From `content/`:

```sh
bun clips/check-cohorts.ts        # every on-screen date in cohorts.json vs src/compute.ts, plus every date typed on a
                                  # carousel or quote card (and every degree in a clip caption); fails if one is stale
bun clips/render-clip.ts          # all style-1 clips (starts wrangler dev --local on :8791 and stops it after)
bash remotion/render-all.sh       # data → 12 sign stills, Aries + Taurus vertical MP4s, all cohort and quote cards
```

Options:

- `bun clips/render-clip.ts --only taurus-2028,aries-three-pass-1997` renders a subset; `--keep-raw` keeps the browser recording in `out/raw/`.
- `BASE_URL=https://rite.mickreal.workers.dev bun clips/render-clip.ts` records the live site instead of a local server. Use it if the local server can't geocode (Nominatim blocked). It writes one real preview row per clip, tagged `ref=content-render`, and runs one preview LLM call each; locally the LLM call fails and the site's fallback text is used, which isn't on screen anyway.
- Locally the script blanks `POSTHOG_KEY` (`--var POSTHOG_KEY:`) and the browser blocks posthog.com, so renders never show up in the funnel.
- `VIDEOS="Aries Leo" bash remotion/render-all.sh` picks which signs get the vertical MP4; `ONLY=signs|videos|cohorts|quotes` renders one group.
- Single renders with the CLI (from `content/remotion/`, after `bun scripts/build-data.ts`):
  `npx remotion still src/index.ts CohortCard out.png --props='{"id":"taurus-2028"}' --browser-executable=/opt/pw-browsers/chromium`
  `npx remotion render src/index.ts SignCardVertical out.mp4 --props='{"sign":"Leo"}' --browser-executable=/opt/pw-browsers/chromium`
  (`remotion.config.ts` already sets the Chromium path, `chrome-for-testing` mode, which a full Chrome binary needs, and `../fonts` as the public dir.)
- `npm run studio` in `content/remotion/` opens Remotion Studio to tweak layouts live.

Dates depend on "today": the clip uses the site's live clock, and the card data uses the clock when `build-data.ts` runs. Pin it with `TODAY=2026-10-19 bun remotion/scripts/build-data.ts` (and `TODAY=` for `check-cohorts.ts`). Re-run the data step before each batch: a card made in October says "open now" or "opens April 2028" as of the day it was built.

## How a clip is made

`render-clip.ts` opens `/start?r=content-render` in a 1080×1920 viewport (deviceScaleFactor 1), with the 480 px mobile column zoomed 2× and pushed below a 430 px caption band. It holds on the intro, types the date (dd/mm/yyyy, ~170 ms a key) and the city, presses "I don't know my birth time" (or types `time` if a cohort has one), waits through the build animation, and holds ~7 s on the summary. Then ffmpeg trims the blank start, scales/crops to 1080×1920 at 30 fps, draws the hook for the first 2.5 s, the first on-screen line while the date is typed and the rest evenly across the build and summary, adds a 0.4 s fade in/out, and encodes H.264 + AAC (a silent track when there's no VO, which some schedulers require). Captions are wrapped using the real font metrics, with "13 May 2026" and "10° Aries" kept on one line.

## Add a cohort (clip)

1. Add an entry to `clips/cohorts.json`: `id`, `label`, `date`, `city`, `time` (null or "HH:MM"), `hook`, `lines` (3–5; a line with "rite.report" is styled as the CTA), and `expect` (the passes and window the lines quote).
2. If the city is new, add its coordinates to `CITIES` in `clips/check-cohorts.ts`.
3. `bun clips/check-cohorts.ts` until it's all ticks, then `bun clips/render-clip.ts --only <id>`.

Birthplace matters by a day: born 1 Apr 1997, London gives 12 May / 2 Feb, New York gives 13 May / 3 Feb (the kit's dates). The check stops on-screen dates drifting from what the site shows for the city typed in the clip.

## Add a carousel

Edit `remotion/carousels.json`: one entry per carousel, `slides` in order, each with `head` / `text` / `tag` / `list` (layout only, the words are the kit's), `kind: "cover"` or `"cta"` for the first and last, and `alt`. Any full date you type must be one `check-cohorts.ts` verifies (its card-facts section); add a fact there if it's new. Then `ONLY=carousels bash remotion/render-all.sh`.

## Add a cohort card or a quote

Edit `remotion/cards.config.json`. Cohorts take birth ranges (`[from, to]`, the first is the headline); the card computes pass months by sampling every birth date in the range, so you never type a pass date. A wide band (a whole sign) gets "One or three exact passes between …" instead of pass months. Quotes take either `text` or `signOpener` (pulls the opener from `src/content/signs.ts`) plus a `footer`. Then `bash remotion/render-all.sh` (or `ONLY=cohorts`).

## Add or change a sign

Signs come straight from `src/content/sign-periods.json` and `src/content/signs.ts`; there's nothing to add. `build-data.ts` copies `signData()`'s selection logic from `src/index.ts` (the stretch happening now, else the nearer of the previous and next); if that function changes, change the copy. The dial angle on a sign card is how far round the cycle someone with Saturn mid-sign is today (top marker = the return point).

## Voiceover

No TTS runs locally (Workers AI is remote-only), so clips render silent. To add a VO:

- Put an MP3 at `clips/vo/<cohort id>.mp3` (git-ignored) and re-render, or pass it once: `bun clips/render-clip.ts --only <id> --vo path/to/vo.mp3`. The audio is padded or cut to the clip length, with a fade at the end; the script warns if the VO is longer than the clip.
- Scripts are in `docs/launch-kit-v2.md` (c), scripts 1–5. Keep the VO under ~19 s or lengthen the summary hold in `render-clip.ts`.
- Narration voice: the deployed site's narration uses Workers AI Deepgram Aura (`TTS_VOICE = "luna"` in `wrangler.toml`). The quickest way to the same voice is the Workers AI REST API with your account token, e.g.
  `curl -X POST https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT/ai/run/@cf/deepgram/aura-1 -H "Authorization: Bearer $CF_TOKEN" -d '{"text":"Born in spring 1997? …","speaker":"luna","encoding":"mp3"}' --output clips/vo/aries-three-pass-1997.mp3`
  (same model and parameters as the narration route in `src/index.ts`; check the Workers AI docs for whether the REST response is raw audio or JSON-wrapped before relying on it). Any other TTS (ElevenLabs, OpenAI) or Mick's own recording works the same way: one MP3 per cohort id.

## Batch export for a scheduler

```sh
bun scripts/export-batch.ts --start 2026-10-19                 # one post a day, alternating a clip and a card
bun scripts/export-batch.ts --plan scripts/plan.example.json   # explicit dates, assets and platforms
```

A plan can also be `{ title, notes, posts }`, where a post may carry `caption`, `alt` (a list for a carousel), `slot`, `kit` and `note`, and may have no `asset` (a text post: it goes in the manifests only). A carousel id as `asset` exports every slide. `--dest <folder>` writes under `out/<folder>/` instead. Example: `scripts/plan-2026-10-weeks-1-2.json` (the kit calendar, days 1–14), whose manifest is committed at `docs/content/2026-10-weeks-1-2.md`.

Writes `out/export/batch-<first date>/` with one file per platform per post, named `<YYYY-MM-DD>_<platform>_<asset>.<ext>` (videos → tiktok, reels, shorts; stills → instagram, x, threads unless `platforms` says otherwise), plus `manifest.csv` (date, platform, file, caption, alt) and `manifest.md` to import into Buffer / Later / Metricool or work from by hand. Captions are a starting point: clip hooks plus "Free preview at rite.report". Edit them in the CSV.
