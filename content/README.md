# Rite content engine

Programmatic content for styles 1, 2 and 6 in `docs/gtm-plan.md` §2. Everything here sits outside the Worker:
the root `tsconfig.json` and `vitest.config.ts` only see `src/` and `test/`, and nothing in `src/` imports from here.

## Setup (once)

- Root deps: `npm ci` in the repo root (wrangler + playwright).
- Content: `cd content && npm ci` (only `aws4fetch`, for the R2 upload). Remotion: `cd content/remotion && npm ci`.
- Tools: bun, ffmpeg (with libfreetype), Chromium. Scripts use `/opt/pw-browsers/chromium` when it exists; set `CHROMIUM=/path/to/chrome` otherwise.
- Clips no longer use Playwright's `recordVideo` (see "How a clip is made"), so Playwright's own ffmpeg build isn't needed; the system `ffmpeg`/`ffprobe` do the encoding, crossfades and VO mix.
- Fonts are in `fonts/` (Bricolage Grotesque, Hanken Grotesk; SIL OFL 1.1, from github.com/google/fonts, licences alongside). The static cuts that ffmpeg uses are generated by `python3 fonts/make-static.py` (needs `pip install fonttools`) and are committed.

## Render everything

From `content/`:

```sh
bun clips/check-cohorts.ts        # every on-screen date in cohorts.json vs src/compute.ts, plus every date typed on a
                                  # carousel or quote card, every degree in a clip caption and every date/degree in a
                                  # VO script; fails if one is stale. --plan <plan.json> also checks each clip against
                                  # Saturn on its posting day ("Today: 10°" lines; the site rounds degrees down)
bun clips/render-clip.ts          # all style-1 clips (starts wrangler dev --local on :8871 and stops it after)
bash remotion/render-all.sh       # data → 12 sign stills, Aries + Taurus vertical MP4s, all cohort and quote cards
```

Or a whole scheduled batch in one command (date check → clips → cards → export folder → zip):

```sh
npm run batch                     # = TODAY=2026-10-19 bun scripts/render-batch.ts --plan scripts/plan-2026-10-weeks-1-2.json --dest 2026-10-weeks-1-2-v2
                                  #   → out/2026-10-weeks-1-2-v2/ and out/2026-10-weeks-1-2-v2.zip
ELEVENLABS_API_KEY=… npm run batch    # the same, with voiceover versions (see Voiceover)
```

`render-batch.ts` works out what to render from the plan's `asset`s (cohort ids → dial clips, `<id>-summary` → `--stills`, `cohort-…`/`quote-…`/`carousel-…`/`…-vertical` → cards). Flags: `--silent`, `--skip-clips`, `--skip-cards`, `--no-zip`, `--from YYYY-MM-DD` / `--to YYYY-MM-DD` (only the posts dated in that range are checked, rendered and exported; default: the whole plan), `--allow-missing-presenter` (an unrendered presenter reel is listed as missing instead of failing the export). Sign verticals (`sign-<slug>-vertical`) in a plan are rendered too. `BASE_URL=http://localhost:8871` reuses a `wrangler dev` you already started.

Options:

- `bun clips/render-clip.ts --only taurus-2028,aries-three-pass-1997` renders a subset; `--keep-frames` keeps the PNG frames in `out/frames/<id>/`; `--silent` never tries VO.
- `BASE_URL=https://rite.mickreal.workers.dev bun clips/render-clip.ts` records the live site instead of a local server. Use it if the local server can't geocode (Nominatim blocked). It writes one real preview row per clip, tagged `ref=content-render`, and runs one preview LLM call each; locally the LLM call fails and the site's fallback text is used, which isn't on screen anyway.
- Locally the script blanks `POSTHOG_KEY` (`--var POSTHOG_KEY:`) and the browser blocks posthog.com, so renders never show up in the funnel.
- `VIDEOS="Aries Leo" bash remotion/render-all.sh` picks which signs get the vertical MP4 (`VIDEOS=all` for all twelve, `SIGNS_OUT=../out/signs-2026-v2` to write them elsewhere); `ONLY=signs|videos|cohorts|quotes|carousels|verticals` renders one group (comma list for several).
- Single renders with the CLI (from `content/remotion/`, after `bun scripts/build-data.ts`):
  `npx remotion still src/index.ts CohortCard out.png --props='{"id":"taurus-2028"}' --browser-executable=/opt/pw-browsers/chromium`
  `npx remotion render src/index.ts SignCardVertical out.mp4 --props='{"sign":"Leo"}' --browser-executable=/opt/pw-browsers/chromium`
  (`remotion.config.ts` already sets the Chromium path, `chrome-for-testing` mode, which a full Chrome binary needs, and `../fonts` as the public dir.)
- `npm run studio` in `content/remotion/` opens Remotion Studio to tweak layouts live.

Dates depend on "today": the clip uses the site's live clock, and the card data uses the clock when `build-data.ts` runs. Pin it with `TODAY=2026-10-19 bun remotion/scripts/build-data.ts` (and `TODAY=` for `check-cohorts.ts`). Re-run the data step before each batch: a card made in October says "open now" or "opens April 2028" as of the day it was built.

## How a clip is made

`render-clip.ts` opens `/start?r=content-render` in a 1080×1920 viewport (deviceScaleFactor 1), with the 480 px mobile column zoomed 2× and pushed below a 430 px caption band, and **renders it frame by frame on a virtual clock** instead of screen-recording it:

- **Capture.** Playwright's `page.clock` fakes the page's `Date`, timers and `requestAnimationFrame` and is paused; an init script pauses every CSS/Web animation (`document.getAnimations()`) and seeks it to the frame's time. For each frame (30 fps, constant) the script runs the scheduled input (clicks, one key at a time), advances the clock by exactly 1/30 s, waits until no request is in flight (so the network takes zero clip time and the build screen always lasts the site's own 3.6 s), then takes a CDP screenshot to `out/frames/<id>/NNNNN.png`. Every frame is rendered exactly once: no dropped, doubled or variable-rate frames (the old `recordVideo` capture was ~20 fps with ~30 % duplicated frames inside motion, which is what read as "jumpy").
- **Screens.** The site swaps steps instantly (`display:none` → `display:flex`). Each swap is crossfaded in post: the last frame of the old screen is held and the new screen fades in over it (`CLIP.xfade`, eased in-out), below the caption band only.
- **Captions** are drawn in the page (real fonts, `text-wrap: balance`, "13 May 2026" and "10° Aries" kept on one line) and fade + rise in (`captionIn`, ease-out) and fade out (`captionOut`), one per beat. The clip fades in from and out to the page background. On the summary a slow eased push-in (`pushScale`) centred on the pass chips runs while the beats play.
- **Pacing.** Hook over the intro and the typing (date ~0.2 s a digit, city ~0.12 s a letter with a little jitter); beat 1 when the build screen shows; beat 2 onwards on the summary once its cards have arrived. Beat length is the VO line + a breath when there is a VO, else reading time (`readBase + readPerWord × words`, at least `minBeat` = caption fade-in + ≥1.5 s settled). A clip is 22–33 s (the kit's 20–40 s; the script warns outside it).
- **Encode.** H.264 High, yuv420p BT.709, CRF 17, constant 30 fps, `+faststart`, AAC 48 kHz: the silent version gets a silent track (some schedulers require audio), the `_vo` version the mixed VO.
- Capture-only CSS hides the text caret (it blinks on a real-time timer, so it flickered frame to frame) and the date field's blue segment highlight.

**Timing constants live in one place: `content/timing.ts`** (`CLIP` for dial clips, `CARD` for card verticals, plus the easing curves). Change a number there and re-render.

## Add a cohort (clip)

1. Add an entry to `clips/cohorts.json`: `id`, `label`, `date`, `city`, `time` (null or "HH:MM"), `hook`, `lines` (3–5; a line with "rite.report" is styled as the CTA), `expect` (the passes and window the lines quote), and optionally `vo`: `{ script, hook, lines }`, the spoken words for the hook and for each caption line (same count as `lines`), spelled out for the voice ("ten degrees Aries", "the thirteenth of May, twenty twenty-six", "rite dot report"; check-cohorts.ts fails on a digit; `[pause 800]` markup is allowed).
2. If the city is new, add its coordinates to `CITIES` in `clips/check-cohorts.ts`.
3. `bun clips/check-cohorts.ts` until it's all ticks, then `bun clips/render-clip.ts --only <id>`.

Birthplace matters by a day: born 1 Apr 1997, London gives 12 May / 2 Feb, New York gives 13 May / 3 Feb (the kit's dates). The check stops on-screen dates drifting from what the site shows for the city typed in the clip.

## Add a carousel

Edit `remotion/carousels.json`: one entry per carousel, `slides` in order, each with `head` / `text` / `tag` / `list` (layout only, the words are the kit's), `kind: "cover"` or `"cta"` for the first and last, and `alt`. Any full date you type must be one `check-cohorts.ts` verifies (its card-facts section); add a fact there if it's new. Then `ONLY=carousels bash remotion/render-all.sh`.

## Add a cohort card or a quote

Edit `remotion/cards.config.json`. Cohorts take birth ranges (`[from, to]`, the first is the headline); the card computes pass months by sampling every birth date in the range, so you never type a pass date. A wide band (a whole sign) gets "One or three exact passes between …" instead of pass months. Quotes take either `text` or `signOpener` (pulls the opener from `src/content/signs.ts`) plus a `footer`. Then `bash remotion/render-all.sh` (or `ONLY=cohorts`).

## Add or change a sign

Signs come straight from `src/content/sign-periods.json` and `src/content/signs.ts`; there's nothing to add. `build-data.ts` copies `signData()`'s selection logic from `src/index.ts` (the stretch happening now, else the nearer of the previous and next); if that function changes, change the copy. The dial angle on a sign card is how far round the cycle someone with Saturn mid-sign is today (top marker = the return point).

## Voiceover

No music, ever: it's added in the app's reel editor. A clip gets a voiceover when its cohort has a `vo` script (from the kit's scripts (c) 1–5; in `clips/cohorts.json`) and a TTS provider is available. Then `render-clip.ts` renders **two files from the same frames**: `<id>_vo.mp4` (VO) and `<id>.mp4` (silent), both captioned.

```sh
ELEVENLABS_API_KEY=… bun clips/render-clip.ts --only aries-three-pass-1997    # one clip, silent + _vo
ELEVENLABS_API_KEY=… npm run batch                                        # the whole weeks 1–2 batch, silent + _vo
```

- **Provider** (`clips/vo.ts`, pluggable via `VO_PROVIDER`):
  - `elevenlabs` (default, chosen 17 Oct 2026): ElevenLabs `eleven_v3`, voice Anna (warm & natural, Australian; `ELEVENLABS_VOICE_ID`, `ELEVENLABS_MODEL` override). The key needs the Text to Speech permission. Spell numbers and dates as words in VO lines for the most natural read. Cached in `clips/vo/cache/`. The Workers AI voice (`rite-admin`) was judged too robotic for social.
  - `rite-admin`: `POST https://rite.mickreal.workers.dev/admin/tts` with `{text, voice?, model?}` and `Authorization: Bearer $RITE_ADMIN_KEY`; the same voice pipeline as the reading's narration, with `[pause 800]`-style markup. `RITE_TTS_URL`, `RITE_TTS_VOICE`, `RITE_TTS_MODEL` override the URL and parameters. Responses are cached in `clips/vo/cache/` (git-ignored) by text, so re-renders don't re-synthesise.
  - `files`: pre-recorded takes at `clips/vo/<cohort id>/00.wav` (hook), `01.wav` (first line) … (`.mp3`/`.m4a` too; `VO_DIR` points elsewhere). Use it for Mick's own recording.
- **No key, or the endpoint 404s / 401s:** no VO. The clip renders silent and the run ends with `NO VOICEOVER (…reason…); rendered silent only` for each clip. Nothing else is tried.
- **Timing to the VO:** every line is synthesised first and measured with ffprobe; each beat lasts `voLead + line + voTail` (at least `minBeat`), the caption for a line fades in `voLead` before it's spoken, and the intro is held longer if the hook needs it. So captions are synced to the spoken words at beat level, and the silent version has the same timing.
- **Mix:** segments are placed at their beat times on a silent bed, then two-pass `loudnorm` to −16 LUFS integrated, true peak −2 dBTP (≤ −1.5 after AAC), 48 kHz stereo, with the clip's fade-out. The render log prints the measured loudness and peak of each `_vo` file.
- `check-cohorts.ts` checks the spoken dates and degrees too ("10 degrees Aries today" against Saturn on the posting day with `--plan`).

### Card and sign verticals

Card verticals (cohort and quote cards) and sign verticals take their VO from `clips/card-vo.json` (`{ "<card id>": paragraph }`, card ids `cohort-<id>`, `quote-<id>`, `sign-<slug>`), spelled out like the clip lines. `scripts/card-vo.ts` (called by `render-all.sh`) gets the take from the same provider (`VO_PROVIDER`; for `files`, `$VO_DIR/cards/<card id>.wav` or `$VO_DIR/signs/<slug>.wav`), sets the video's length to the take + 1.6 s (`CARD.voLead` + `CARD.voTail`; the `seconds` prop, applied by `calculateMetadata`), renders, and writes the silent file plus `<name>_vo.mp4` (the take at 0.5 s, −16 LUFS). Without a take the length is estimated from the text at 2.6 words a second, so a silent render is already paced for its voice. The motion (brand.tsx) scales with the length: build-up over the first part, key line glowing at 1/3 and 2/3, one branding refresh in the quiet gap.

### Generating takes outside the renderer

`bun scripts/vo-lines.ts --plan <plan.json>` (or `--signs`) prints one `path<TAB>text` row per take (`<cohort id>/NN` for a dial clip, 00 = hook; `cards/<card id>`; `signs/<slug>`). Generate each as `<dir>/<path>.mp3` with ElevenLabs v3 Anna, then re-render with `VO_PROVIDER=files VO_DIR=<dir>`. Examples: `scripts/vo-lines-2026-11-weeks-3-4.tsv`, `scripts/vo-lines-signs.tsv`.

## Presenter reels (Anna, AI presenter)

Anna is the face for the voice of Rite: an AI presenter generated in ElevenLabs (still: Seedream 5 Pro; talking head: Creatify Aurora, 720p; voice: Anna, `eleven_v3`). She is always labelled "AI presenter" on screen and is never presented as a customer, a reader or Mick. Everything lives in one ElevenLabs flow ("Anna presenter"): the approved vertical still, the VO takes and the lip-sync nodes.

**Use her sparingly.** A talking head costs about $0.17 a second of finished video (≈8.5k credits per 10 s; a 46 s clip is ≈$8), against $0 for cards. So she gets the lines a person lands better than a graphic: the hook, an opinion or challenge ("ask them which day"), sometimes the CTA. Dates, windows, passes and phases stay on cards, where the numbers are exact and legible. Aim for 10–15 s of Anna in a reel, and test any new set-up with a 10 s clip before a long one.

To make one:

1. Write the reel's VO as one take (ElevenLabs v3, Anna) and get word timings (Scribe, free in the flow).
2. Choose which spans are Anna; cut those spans from the take (at a pause), lip-sync each onto the still in the flow (Aurora, 720p, one generation), download the MP4s.
3. Add the reel to `remotion/presenter.json`: segments (`presenter`, `window`, `phases`, `line`, `cta`) with their `from`/`to` and the word-timed cues. Put the take (`vo.mp3`) and the presenter clips in `out/presenter/<id>/`.
4. `bash remotion/render-presenter.sh <id>` → `out/presenter/<id>.mp4` (CRF 17, 30 fps, −16 LUFS). Segments crossfade over 0.45 s, ending on their cue; the presenter part gets a slow 3 % push-in and burned-in captions.

## Launch calendar on the real launch day

The 28-day calendar (weeks 1–2 and 3–4) is written for day 1 = 19 Oct 2026. On domain day, move it onto launch day L (a Monday) and render it in one go:

```sh
LAUNCH=2026-11-16 ELEVENLABS_API_KEY=… npm run launch     # = scripts/launch-plan.ts --render
```

`scripts/launch-plan.ts` joins both plans, moves every post by the same number of days into `scripts/plan-launch.json`, then runs `render-batch.ts` with `TODAY=L` into `out/launch/` (+ zip). The date check fails on any clip whose "Today" degree is stale on its new day. Before rendering it prints every post whose wording is tied to the calendar ("right now", "this year", "four weeks") or names a date that was still ahead on its original day and has passed by its new one. Reread or rewrite those first. The week-4 posts are pegged to Saturn's station on 11 Dec 2026, so the later L is, the more of week 4 needs rewriting. Presenter reels are exported from `out/presenter/` like any other asset (render them first with `npm run presenter -- <id>`).

## Batch export for a scheduler

```sh
bun scripts/export-batch.ts --start 2026-10-19                 # one post a day, alternating a clip and a card
bun scripts/export-batch.ts --plan scripts/plan.example.json   # explicit dates, assets and platforms
```

A plan can also be `{ title, notes, posts }`, where a post may carry `caption`, `alt` (a list for a carousel), `slot`, `kit`, `note`, `time` (`"HH:MM"` Brisbane time: the slot the scheduled upload gives it, default 09:00) and `ref` (an id for a text post, e.g. `kit-post-3`), and may have no `asset` (a text post: it goes in the manifests only). A carousel id as `asset` exports every slide. `--dest <folder>` writes under `out/<folder>/` instead; `--from` / `--to` keep only the posts dated in that range. Examples: `scripts/plan-2026-10-weeks-1-2.json` (the kit calendar, days 1–14) and `scripts/plan-2026-11-weeks-3-4.json` (days 15–28), whose manifests are committed at `docs/content/2026-10-weeks-1-2.md` and `docs/content/2026-11-weeks-3-4.md`.

Writes `out/export/batch-<first date>/` with one file per platform per post, named `<YYYY-MM-DD>_<platform>_<asset>.<ext>` (videos → tiktok, reels, shorts; stills → instagram, x, threads unless `platforms` says otherwise), plus `manifest.csv` (date, platform, file, caption, alt, other_version), `manifest.json` (the same per post, read by `scripts/upload-week.ts`) and `manifest.md` to import into Buffer / Later / Metricool or work from by hand. Captions are a starting point: clip hooks plus "Free preview at rite.report". Edit them in the CSV. When a clip has a `_vo` render, both versions are exported (`…_<asset>_vo.mp4` and `…_<asset>.mp4`); the CSV's `file` is the VO version and `other_version` the silent one. Card verticals last their voiceover + 1.6 s (10 s with no VO text; `CARD` in `timing.ts`): eased fade in, eased push-in to 1.035×, eased fade out, rendered as one composited layer so text doesn't shimmer. For the whole render → export → zip in one go, see `scripts/render-batch.ts` / `npm run batch` above.

## Scheduled render (GitHub Actions)

`.github/workflows/render-week.yml` renders next week's posts every **Thursday 02:00 UTC** (12:00 Brisbane) and uploads them to R2, so the week is ready four days before its Monday. Build 5 (auto-posting via Postiz) reads the manifest it writes.

What a run does, on `ubuntu-24.04` (bun, ffmpeg, the en_GB locale, Chromium from Playwright with `CHROMIUM` set to its path, `npm ci` in the root, `content/` and `content/remotion/`):

1. **Picks the week** (Monday to Sunday; next Monday unless dispatched with one) **and the plan:** `scripts/plan-launch.json` while the week is inside it; for a week past its last date, `scripts/rolling-plan.ts --week <monday>` generates one (keeping the launch plan's posts if the week overlaps its end).
2. **Date check:** `bun clips/check-cohorts.ts --plan` on that week's posts (`TODAY` = the Monday: on-screen dates, degrees and VO), then `bun scripts/check-captions.ts --plan` (a caption or alt text naming a date that was ahead when it was written and has passed by its posting day, e.g. a launch plan moved to a later launch day). A stale date fails the run; calendar wording like "right now" or "four weeks" is a warning on the run to reread.
3. **Renders only that week:** `render-batch.ts --from <monday> --to <sunday> --allow-missing-presenter`, with voiceover (`VO_PROVIDER=elevenlabs`) when the `ELEVENLABS_API_KEY` secret is set, silent otherwise. Clips run against the local `wrangler dev --local` that `render-clip.ts` starts (local D1 and KV, no AI binding needed): no Cloudflare token is needed, and the workflow has none. Voiceover takes are cached between runs (`clips/vo/cache`), so a reused asset doesn't spend credits again. Presenter reels (Anna) aren't rendered in CI: a presenter post is listed with `missing: true` and `auto: false`.
4. **Uploads** with `scripts/upload-week.ts --week <monday>` (below), and keeps the manifests (not the media) as a run artifact for 30 days.

**Failure:** if the date check, a render or the upload fails, the job fails and GitHub emails the repo owner. Keep that on: GitHub → your avatar → Settings → Notifications → System → Actions → "Only notify for failed workflows", with Email ticked. A failed Thursday run leaves four days to fix it and run it again by hand.

### Rolling plan

`scripts/rolling-plan.ts --week <monday>` builds a week from what's already written and rendered: one TikTok + Reels video a day, alternating (by day number) a dial clip from `clips/cohorts.json` and a card or sign vertical (cohort cards, quote cards, the twelve signs); one X + Threads post from the kit's list (`docs/launch-kit-v2.md` (d)) on Monday, Wednesday and Friday; one Instagram carousel on Saturday.

- Nothing (asset, or kit post) repeats within 21 days. History: the previous three weeks' manifests in R2 when the `R2_*` credentials are set, else `out/weeks/*/manifest.json`, plus the launch plan.
- Nothing tied to the calendar: no "today / this year / right now" wording (the list in `launch-plan.ts`, plus "next spring" and the like), and no date that was still ahead when the kit was written (17 Oct 2026) and has passed by the posting day. "Saturn stops on 11 December" drops out after 9 Dec 2026, a "Dec 2026" after December.
- Captions: the launch plan's caption for the same asset if it passes the same test, else the hook or kit text plus "Free preview at rite.report". Alt text likewise.
- The week has to pass `check-cohorts.ts --plan`; a clip that fails on its posting day is swapped and the check re-run.
- When a pool runs dry the slot takes the other kind of video, or stays empty with a `!` note in the plan's notes, never a repeat. With today's material the dial clips run out first (about seven are evergreen), so most weeks have more cards than clips, and one Monday in three has no X post (eight kit posts are evergreen). More cohorts, quote cards or kit posts widen the pools. New Anna reels stay a manual choice (they cost money).

### Bucket layout and manifest

```
weeks/latest.json                                   { week_start, manifest, manifest_url, updated_at } of the newest week
weeks/<monday>/manifest.json                        the week
weeks/<monday>/<16-char random id>/<date>_<asset>.mp4, <date>_<asset>_vo.mp4, <date>_<carousel>-NN.png
```

Media sit in a random folder per upload, so their URLs can't be guessed from the date. The manifest's path is predictable and, on a public bucket, readable by anyone who guesses it (which shows next week's media a few days early). Build 5 (og-content-system's `import_rite.py` on Mick's Pi) reads them by that public URL, so don't block them with a WAF rule unless the importer is given another way in. Uploading a week again makes a new random folder and replaces its manifest; `latest.json` only moves forward.
